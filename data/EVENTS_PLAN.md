# 事件生成方案（按 v2 文档 事件.docx）

## 一、总体结构

事件按**四池**管理，分别存放在：

- `data/fixed/events.gd`　固定池（日期强制 / 状态触发）
- `data/community/events.gd`　社区池
- `data/family/events.gd`　家庭池
- `data/neighborhood/events.gd`　邻里池

`GameData.gd` 不再保存事件数组，改用 `preload` 汇总四池，避免 `class_name` 全局缓存时序问题。

**游戏总时长 14 天**（`GameData.TOTAL_DAYS = 14`）。结局由 `data/endings.gd`（`GameEndings.judge`）管理：每次结算时判定——心情/免疫力/物资任一 ≤ 0 触发对应坏结局；**第 14 天结算**按三个开关（值守度=1 / 儿子完美结局=1 / 你是我的好爸爸=1）给出完美结局「在结束的那一天」或普通好结局「平庸却坚定」。**结局以卡片形式替换当天的结算卡**（结局配图 art 插在卡上，当前留空待统一导入），滑动结局卡后重新开始游戏。

### 概率与权值

- 低概率 `weight = 2`
- 中概率 `weight = 3`（默认）
- 高概率 `weight = 5`
- 条件不满足的事件权值视为 0，退出当日竞争
- 固定池现仅「日期强制 / 状态触发」，无独立概率事件（`chance` 机制已取消，统一用 `weight` 自然竞争）

### 选项方向说明（重要）

> **往哪个方向滑动由卡牌编辑在运行时按「动态选项数」决定，事件代码里不要写方向。**
> 即使选项没有任何增减，事件代码也无需（也不会）指定 ←/→/↑。
> 卡牌编辑内部映射：1 个 → 上；2 个 → 左 / 右；3 个 → 左 / 上 / 右。

- 每天生成卡牌时，`Main._show_current` 调用 `GameData.active_options(ev, stats, flags, day)` 做两件事：
  1. 过滤掉 `cond` 不满足的选项；
  2. 把筛选后的选项按顺序交给卡牌编辑，由卡牌编辑按数量决定方向（不读取事件里的 `dir`）。
- **取舍**：卡牌编辑只接收筛选后的选项，事件逻辑集中在 `GameData`，卡牌保持纯展示。

### art 字段约定

- 事件级 `art`、选项级 `art` 当前**全部为空 `""`**，以后按 `data/IMAGE_LIST.md` 的编号统一导入。
- 导入后：事件级 `art` 对应 `res://art/<图名>.png`（描述部分背景）；选项级 `art` 对应 `res://art/<图名>.png`。
- 文中各事件标注的 `（图：a1 / a2 …）` 仅指 `IMAGE_LIST.md` 里的计划编号，代码里仍写 `""`。

### 2. 接龙时间（特殊卡：三段式）

- **id**：`ordering`
- **池**：固定
- **触发**：第 1 天，之后每 4 天（1,5,9,13）
- **类型**：`shopping`（独立 UI 流程，见下）
- **art**：`""`（描述图：b1 普通版 / b2 志愿者版；物资卡：b3）
- **基础效果**：物资 +15
- **描述两版**（按开关 `volunteer` 判定提交哪一版）：
  - 普通版：5 样可选 3 样
  - 志愿者版：7 样可选 4 样
- **池中只保存描述（0 个选项）**：开场卡显示既有的灰色「滑动任意方向」提示，任意方向滑动进入选择物资卡
- **三段式流程**：
  1. **统一卡（CardView 生成）**：标题「接龙时间」+ 描述，**无选项**（0 个选项 → 任意方向滑动）。
  2. **选择物资卡（单独脚本生成，或并入 CardView 新分支）**：同为卡牌尺寸，但**整张卡都是选物资（m 选 n），没有上下两半之分**，选项（物资项）在**左右两列整齐排布**；选满规定数量（普通版 3 / 志愿者版 4）后，可向任意方向滑动确认。
  3. **统一 result 卡（CardView 生成）**：触发提交后的结果文本，同样按 `volunteer` 出普通版 / 志愿者版。
- 即：`标题 + 描述 + 单选（统一生成）` → `单独生成的选择物资卡` → `触发的 result（统一生成）`。

## 七、事件代码实现约定

- 四维初值：`mood=30, immunity=30, supplies=30, harmony=30`
- 计数初值：`eggs=0, noodles=0`
- 开关初值：大部分 `false`，`account=true`
- 效果写法：`effects` 直接写 `{ "mood": ±n, ... }`
- 计数增减：用 `dec: { "eggs": -1 }`（会合并到 `flags`）
- 状态开关：用 `set: { "crisis": true }`
- 条件阈值：
  - `< 50` 用 `max_stats: { "x": 49 }`
  - `< 70` 用 `max_stats: { "x": 69 }`
  - `≥ 50` 用 `min_stats: { "x": 50 }`
- 多选一条件用 `any: [...]`
- **事件代码不写滑动方向**，方向由 `GameData.active_options` 按动态选项数决定（1→上 / 2→左右 / 3→左上右）
- 固定池不再使用 `chance` 概率字段，统一用 `weight` 竞争
