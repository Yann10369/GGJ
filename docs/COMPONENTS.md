# Grow 实现说明

## 唯一流程

`Main.tscn → Main.gd → GameManager.run (GrowRun)`。

Main 的任务是显示状态并调用 `act`、`choose`、`purchase`、`continue_run`。所有入口按阶段验证，不合法调用返回 false。动画、按键和按钮不直接改数值，也不重新抽事件。

单局阶段依次是 `MORNING → EVENT → RESULT → EVENT / NIGHT → MORNING`。发生结局时走 `NIGHT → RECAP → ENDING`。结果、结算和回顾均需要主动继续，因此玩家可以完整阅读编剧文案。

## 调度与因果

事件从清单加载，`shown` 记录已处理事件的日期，整局不清空。`pending` 保存种子最早日期与消息真相；`eligible_since` 记录连续符合条件的起点。

固定事件优先，随机填充每日 A / B 卡位。选项实时应用后再选择下一张，避免旧队列忽略刚发生的 Flag 变化。每次抽取重新检查条件与间隔。空池跳过，不用开场卡作为兜底。关键事件到期优先；接龙日允许 B 卡位让给到期社区剧情，维持每天最多两张。

普通事件权重为 2 / 3 / 5。低心情加强家庭矛盾，低免疫力或较高暴露风险开放健康事件；高和睦加强正面社区事件。尚未到最早日期的种子，即使同时在随机池中也不会提前出现。

`final_day` 初始取目标时长与最晚剧情期限后一日的较大值。临近结束产生的关键后续可以顺延尾声；可重复小事件不会无限推迟结局。结局是否成立只在夜间统一判断。

## 表现

Card 保留纸质卡面、已有插画、堆叠、拖动和飞出动画。背景牌使用中性卡背，不展示未经触发的未来剧情。过滤条件后恰好两个选项使用滑动，并在卡下方显示常驻方向说明；其他数量只生成决策按钮，选择后淡出。卡牌区裁剪旋转与卡背，底部决策区独立布局；尺寸改变时更新整个牌堆。水平手势可从正文开始，短拖动和纵向阅读不提交选择。隐藏效果与未来 Seed 不预告，长文本可滚动。

ShoppingCard 只使用单局已经抽好的商品列表。选择满额才能提交，额外点击不会偷偷增加采购数量。主界面和状态机共同防止重复选择。

CommunityView 按和睦切换四档窗户、灯光、邻居和配送车表现。音频沿用已有翻卡、选择、滑动和结局资源。复杂场景插画与新环境音不属于本次核心流程重构。

## 保留的旧骨架

`ScavengePhase`、`SurvivalPhase`、`Character`、`CardData`、`EventData`、`CardManager` 保留供参考，当前主场景不实例化它们。CardManager 不再自动加载；不要将旧的拾荒循环重新接回 GrowRun。要添加剧情，编辑 JSON，而不是恢复旧内联事件或另一套 GameManager 状态。

## 测试入口

`tests/test_grow.gd`：固定种子的完整单局与规则回归。`tests/test_ui.gd`：真实主场景的按钮、手机、多选项、遮罩与重开检查。`tests/capture_ui.gd`：在图形模式下生成布局检查截图。

JSON 必须包含在导出包里。`export_presets.cfg` 的 Windows 预设包含 `data/*.json`；如果另建平台预设，需要保留这个非资源文件过滤项。
